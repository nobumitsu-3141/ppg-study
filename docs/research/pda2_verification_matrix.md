# PDA 第2版 検証表 ── 「何を主張しているか」と「何がそれを保証しているか」の対応

作成 2026-09-05（監査 7 巡目）。

## なぜこの表が要るのか

6 巡の監査で毎回改善点が見つかった。理由は監査のやり方にある。
「コードを読んで思いつく限りの点を検べる」やり方は、**検べ終わったという状態が定義できない**。
新しい視点（凍結版との同一性、公平性、検査の網羅性、文書と実装の食い違い）を持ち込むたびに
新しい欠陥が見つかるのは当然で、視点の数は決めていなかった。さらに、直した効果を文書に書くだけで
**合否のある検査にしていなかった**ので、次の変更で黙って消えた（6 巡目 K9）。

この表は監査の対象を有限に固定する。行は（1）すべての数値定数、（2）すべての不変条件、
（3）すべての修正記録、（4）文書の主張。各行は「検査名」「監視表」「in silico では検べられない
（理由）」のどれかで終わる。**空欄が無くなった状態を「改善点が無くなった」の定義とする。**
以後 pda2 を変えるときは、この表の該当行を先に更新し、対応する検査を先に書く。

記号: T1〜T11 = `25_pda2_validate.py`、I1〜I9 = `28_pda2_invariants.py`、
S26-n = `26_pwdb_compare.py --selftest` の n 番目の検査、S27-n = `27_threshold_sensitivity.py --selftest`、
表 1・1a・1b・2・2a・2b・2c・3 = 26番の出力の表、A/B = 27番の感度解析の層。
